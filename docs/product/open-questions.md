## OPEN 保留事項・今後の検討

- [ ] 学部・学科コードの最新版と、大学院の研究科コードを大学に確認する
- [ ] 同じドメインのアドレスを、教職員や留学生も持っているか確認する
- [ ] 有効期限の延長の仕組み（留年、医学部医学科などの6年制、大学院進学、編入）
- [x] 失効時に、進行中の取引、公開中の商品をどう扱うか → 商品は取り下げ、承認待ちの購入希望は期限切れ、取引中の取引はキャンセルして返金（[ADR 0033](../decisions/0033-account-expiry-and-daily-job.md)）
- [ ] 失効時に、未出金の売上をどう扱うか（決まるまでは売上の記録を変えない。[ADR 0033](../decisions/0033-account-expiry-and-daily-job.md)）
- [ ] 自動完了を導入するか（導入する場合は7日が妥当か、導入しない場合は止まった取引をどう扱うか）
- [ ] 購入希望の承認期限（48時間）が、決済サービスのオーソリ有効期限と合っているか（フェーズ1のモックでは48時間で実装。[ADR 0022](../decisions/0022-deal-request-item-status-and-approval-deadline.md)）
- [ ] 手数料率（決まるまでは暫定の初期値 5% を使う。[ADR 0017](../decisions/0017-fee-rounding-and-provisional-rate.md)）
- [ ] 決済代行サービスの選定と、出金先にPayPayを指定できるか
- [x] 共有リンクをログインしていない人が開いたときの表示 → ほかの画面と同じくログインを求め、ログイン後に商品ページへ戻す（[ADR 0020](../decisions/0020-share-link-login-and-copy-only.md)）
- [x] 禁止出品物の規約（試験の答案、医薬品、酒類など）→ [ITEM-1](03-listing.md) に一覧を書いた。自動判定はせず、規約と管理者の停止で対応する
- [ ] 商品Q&Aを付ける場合の形（公開の書き込み欄にする想定）
- [ ] 利用規約とプライバシーポリシー（学生証の保持目的と期間を含む。保持期間は失効・削除から3年で確定し、再提出前の画像も含む。[ADR 0014](../decisions/0014-student-card-retention.md)。本文は #65 で書く）

* [ ] 教職員の利用条件（受け付けるメールドメイン、学生との判定方法、取引成立時に開示する情報、出品時の確認書類、アカウントの有効期限）

## OPEN-DERIVED 分割時に見つかった確認事項

元文書から読み取れず、実装時に判断が必要になる点（2026-10-14 の分割作業で追加）。

- [x] 商品の「取り下げ」が取引中にもできるか（[ITEM](03-listing.md) は「いつでも」、[DEAL-4](05-deal-flow.md) は取引成立後のキャンセルを双方同意に限定しており、両立の仕方が未定） → 取引中は取り下げ・編集とも不可。取り下げは下書き・公開中・購入希望ありだけ（[ADR 0016](../decisions/0016-item-edit-withdraw-rules.md)）
- [x] 購入希望ありの商品で、購入希望がすべて期限切れ・取り下げになったときに商品ステータスを公開中へ戻すか → 戻す。公開日時は変えない。商品の取り下げ時は購入希望を却下して枠を解放する（[ADR 0022](../decisions/0022-deal-request-item-status-and-approval-deadline.md)）
- [ ] 管理画面「ユーザー」「出品・取引」「設定」のデザイン（キャンバスには「学生証審査」だけがある）
