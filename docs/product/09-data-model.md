# データモデル（要件）

> 関連: [技術：DB](../tech/database.md) / [用語集（テーブル名・列名の対応）](../glossary.md)

## DATA データモデル

主なデータは6種類です。決済まわりは、本番の決済代行サービスのIDを後から持たせられる形にしておきます。

| データ | 主な項目 |
| --- | --- |
| User（ユーザー） | ID、メールアドレス、学籍番号、入学年度、学部、有効期限、状態（有効・停止・失効・削除）、出品者の承認状態、退学を申請した日時 |
| StudentCard（学生証） | ユーザーID、画像の保存場所、審査状態、審査した人、審査日時、閲覧記録、再提出で置き換えた日時、削除予定日（失効・削除日 + 3年） |
| Item（商品） | 出品者ID、カテゴリ、タイトル、説明文、状態、価格、キャンパス、カテゴリ別の追加項目、ステータス、共有用ID |
| ItemImage（商品画像） | 商品ID、画像の保存場所、表示順 |
| Transaction（取引） | 商品ID、購入者ID、出品者ID、金額、支払い方法、手数料率、手数料、出品者の売上、ステータス、ステータス（購入希望・却下・期限切れ・取引中・キャンセル・完了）、承認期限、学籍番号を開示した日時、出品者が確認モーダルに同意した日時、受け渡しトークン（QR・リンク・コード）とその有効期限、キャンセルへの双方の同意日時、受け渡しが完了した日時と完了方法（QR・リンク・コード・自動） |
| Payment（決済・出金） | 取引ID、種別（支払い・返金・出金）、支払い方法（売上の確定・出金では空）、金額、ステータス（処理中・成功・失敗）、外部サービスのID（モックでは空） |

- 上表の Transaction の「ステータス」が重複しているのは元文書のまま。ステータスは1列（購入希望・却下・期限切れ・取引中・キャンセル・完了）として扱う。
- 上表は主な項目のみ。認証に必要なデータ（パスワードハッシュ、セッション、認証コード、登録端末、送信数の記録など）は [tech/auth.md](../tech/auth.md) と [tech/database.md](../tech/database.md) から導く。
- 設定（Setting）は1行だけで、手数料率と、最後に変更した日時・管理者を持つ（[ADR 0034](../decisions/0034-admin-users-deals-settings.md)）。
- 支払い方法は購入希望のときに購入者が選び、Transaction と Payment の両方に持つ。出金も取引ごとに1行の Payment として記録する（[ADR 0021](../decisions/0021-transaction-payment-columns.md)）。
