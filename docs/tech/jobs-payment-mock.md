## JOBS 定期処理と決済モック

### JOBS-1 定期処理

Cloud Scheduler から Cloud Run の内部用エンドポイントを定期的に呼び出します。Cloud Scheduler の無料枠に収まるよう、ジョブは2つにまとめます。

| ジョブ | 間隔 | 処理内容 |
| --- | --- | --- |
| 短周期ジョブ | 15分ごと | 48時間たった購入希望の期限切れ処理と枠の解放、期限切れのログインコード・受け渡しトークンの削除、24時間更新のないパスワードの入力ミスの記録の削除、自動完了（暫定）と催促通知 |
| 日次ジョブ | 毎日深夜 | アカウントの失効、削除予定日を過ぎた学生証画像の削除、DBのバックアップ |

- 内部用エンドポイントは、Cloud Scheduler のサービスアカウントからの呼び出しだけを受け付けるようにします。
- 認証コード（`verification_codes`）は送信数の制限と全体の送信数に使うため、期限が切れても作ってから24時間は消しません（[AUTHN-6](auth.md)）。

### JOBS-2 決済モック

決済は、処理の窓口（インターフェース）を1つ決め、当面はモックの実装を差し込みます。本番では、同じ窓口に Stripe Connect や PAY.JP の実装を差し替えます。

| 操作 | タイミング | モックでの動き |
| --- | --- | --- |
| 枠の確保 | 購入希望 | 成功したことにして記録する |
| 代金の確定（預かり） | 出品者の承認 | 記録する |
| 枠の解放 | 却下・期限切れ | 記録する |
| 返金 | 双方同意のキャンセル | 記録する |
| 売上の確定 | 受け渡し完了 | 手数料を引いた金額を出品者の売上として記録する |

- 本番の決済サービスからの通知（Webhook）を受けるエンドポイントは、最初から枠だけ用意しておきます。
