# ADR 0017: 手数料の端数・暫定の料率と、出品の編集ルート

- 日付: 2026-10-20
- 状態: 採用
- 関連する章ID: PAY-2, FE, ITEM, DB

## 背景

出品画面（#20）には、価格の下に「手数料 [料率]」「受け取り見込み ¥[金額]」を表示するデザインがある。しかし、

- 手数料率は [未決事項](../product/open-questions.md)（「手数料率」）で、料率を保存するテーブルも取得する API もなかった。
- 手数料の1円未満の扱いが決まっていなかった（server/CLAUDE.md に「実装時に確認する」とあった）。

また、出品の編集のルートは `/items/:shareId/edit` だったが、編集用の API（`GET`・`PUT /items/{itemId}`）は共有用ID ではなく商品ID を受け取るため、画面から API を呼べなかった。

## 決定

- 手数料 = 商品価格 × 手数料率 の1円未満を**切り捨て**る。出品者の売上 = 商品価格 − 手数料。出品画面の見込み表示と、取引に適用する計算（DEAL-1）で同じ計算を使う。
- 料率は1行だけの `settings` テーブル（`fee_rate_bp`）に保存し、ログインした利用者が `GET /settings/fee-rate` で取得できるようにする（#77）。変更 API は管理画面（#36）で作る。
- 料率そのものは未決のまま、管理画面で設定するまでの暫定の初期値を **500ベーシスポイント（5%）** にする。
- 出品の編集ルートを `/sell/:itemId` にする（新規は `/sell`）。

## 理由と検討した選択肢

| 選択肢 | 良い点 | 悪い点 |
| --- | --- | --- |
| 手数料を切り捨て（採用） | 出品者に有利で、説明しやすい | 運営の取り分が最大1円少ない |
| 手数料を四捨五入・切り上げ | 運営の取り分がわずかに増える | 出品者への説明が増える |
| 見込み表示を出さず、料率API を後回し | server の作業が増えない | デザインの見込み表示が出せない |
| 編集ルートを `/sell/:itemId`（採用） | 既存 API のまま。新規と同じ画面で扱える | FE-1 の表を変える必要がある |
| 共有用ID で自分の商品を取る API を追加 | ルートを変えずに済む | server の作業が増え、同じ商品を2種類のIDで取る口ができる |
