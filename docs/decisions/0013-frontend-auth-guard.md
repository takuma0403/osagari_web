# ADR 0013: 画面の認証ガードとログイン後の行き先

- 日付: 2026-10-17
- 状態: 採用
- 関連する章ID: FE-1, AUTH-1, AUTHN-3, AUTHN-5

## 背景

ログイン必須のアプリだが、どの画面でログインを求めるか、ログイン後にどこへ進むか、ログイン済みの人が認証の画面を開いたときどうするかが仕様になかった。また、未決事項「共有リンクをログインしていない人が開いたときの表示」（[product/open-questions.md](../product/open-questions.md)）が `/items/:shareId` のガードに関わる。

## 決定

- ログイン状態は起動時に `GET /me` で確かめる。どの API でも `401 unauthorized` が返ったら未ログインに戻す（ログインのパスワード違い `invalid_credentials` は対象外）。
- ログイン前だけの画面（`/login`、`/signup*`、`/password-reset*`、`/recheck`）と、誰でも見られる画面（`/terms`、`/privacy`）を除き、すべてログインを求める。未ログインならログイン画面へ送る。
- ログイン画面へ送るときは開こうとしていたページを覚えておき、ログイン（再確認を含む）に成功したらそこへ戻す。なければ商品一覧。
- ログイン済みの人がログイン前だけの画面を開いたら商品一覧へ送る。
- 共有リンク（`/items/:shareId`）も、未決事項が決まるまではログインを求める（未決事項は未決のまま）。

## 理由と検討した選択肢

| 選択肢 | 良い点 | 悪い点 |
| --- | --- | --- |
| ログイン後は開こうとしていたページへ戻す（採用） | 共有リンクや取引の画面から来た人がそのまま続けられる | 行き先を画面間で持ち回る必要がある（location.state。URL には載せない） |
| ログイン後は常に商品一覧 | 単純 | 共有リンクを開いた人が商品を探し直すことになる |
| ログイン済みでも認証の画面はそのまま出す | 単純 | 二重ログインや、ログイン中に新規登録へ進む混乱が起きうる |
