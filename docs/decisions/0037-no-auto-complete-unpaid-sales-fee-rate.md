# ADR 0037: 自動完了は導入しない・失効時の未出金売上・手数料率の確定

- 日付: 2026-10-29
- 状態: 採用（手数料率は [ADR 0017](0017-fee-rounding-and-provisional-rate.md) の暫定値を確定させる）
- 関連する章ID: DEAL-3, DEAL-5, AUTH-3, PAY-1, PAY-2, JOBS-1（利用規約 第５条・第７条）

## 背景

利用規約（#65、[ADR 0036](0036-terms-and-privacy.md)）を書くにあたり、規約に書く必要がある次の未決事項（[product/open-questions.md](../product/open-questions.md)）を決めた。

- 自動完了を導入するか（導入する場合は7日が妥当か、導入しない場合は止まった取引をどう扱うか）
- 失効時に、未出金の売上をどう扱うか
- 手数料率

## 決定

- **自動完了は導入しない。** 受け渡しを完了させるのは購入者の操作だけ、という決まりを変えない。取引が止まったときは、当事者が窓口に申し出て、管理者が事情を確かめて取引をキャンセルする（既存の管理者によるキャンセル。[ADR 0034](0034-admin-users-deals-settings.md)）。DEAL-5 は「導入しない」として残し、番号は変えない。
- **失効・削除時の未出金の売上**は、失効・削除の日から**6か月以内**に窓口へ申し出れば出金する。6か月を過ぎたら出金を求められない。有効期限が近づいた利用者には出金を促す。売上の記録そのものは失効時に変えない（[ADR 0033](0033-account-expiry-and-daily-job.md) のまま）。
- **手数料率は 5%（500ベーシスポイント）で確定する。** 規約には率を書かず、「アプリに表示する率」とする。管理画面から変えられること、取引ごとに成立時の率を記録することは変えない。

## 理由と検討した選択肢

| 選択肢 | 良い点 | 悪い点 |
| --- | --- | --- |
| 自動完了を導入しない（採用） | 「商品を受け取る前にお金が渡らない」を守れる。日次ジョブが増えない | 止まった取引には運営の手作業が要る |
| 成立から7日・14日で自動完了 | 運営の手作業が減る | 受け取っていない購入者の代金が動く。決まりの変更が要る |
| 未出金売上は6か月間申し出で出金（採用） | 利用者の権利を一定期間守り、運営が無期限に預かり続けない | 窓口での手作業が要る |
| 失効時に権利が消える | 実装も運用も要らない | 利用者に一方的に不利で、消費者契約法上の問題になりやすい |
| 期限なしで申し出に応じる | 利用者にとって最も安全 | 売上を無期限に持ち続ける |
| 規約に率を書かない（採用） | 率を変えても規約の改定が要らない | 規約だけを読んでも率がわからない |

## 影響

- 更新：[product/05-deal-flow.md](../product/05-deal-flow.md) DEAL-5、[product/01-account-auth.md](../product/01-account-auth.md) AUTH-3、[product/06-payment.md](../product/06-payment.md) PAY-1・PAY-2、[tech/jobs-payment-mock.md](../tech/jobs-payment-mock.md) JOBS-1、[docs/README.md](../README.md) の対応表、ルートの [CLAUDE.md](../../CLAUDE.md) の「守るべき決まり」、[product/open-questions.md](../product/open-questions.md)。
- API 契約：受け渡しの完了方法の `auto`（自動完了）と、短周期ジョブの説明に「未定」の記述が残っている。`auto` を外すかどうかは API 契約・DB の変更になるため、別の issue で扱う（あわせて glossary の完了方法、server の列挙型・テスト・`cmd/api/main.go` のコメント、テストの「暫定の 5%」のコメントを直す）。
- 失効後の出金の受け取り先（PAY-5 では未登録）は、本番の決済を始めるときに決める。試験運用の間はお金が動かないので問題にならない。
- 実装（別の issue）：有効期限が近づいた利用者への出金のお願い。6か月以内の申し出の出金は、窓口が決まってから運用で行う。
