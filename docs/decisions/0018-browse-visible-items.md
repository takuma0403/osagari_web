# ADR 0018: 一覧・検索と商品ページに出す商品の範囲

- 日付: 2026-10-21
- 状態: 採用
- 関連する章ID: BROWSE, DEAL-1, AUTH-3

## 背景

[BROWSE](../product/04-browse-search-share.md) は「公開中の商品の一覧」とだけ書いていて、次の点が決まっていなかった。一覧・検索・詳細の API（#21）の着手時に決めた。

- 購入希望ありの商品を一覧に出すか。[DEAL-1](../product/05-deal-flow.md) では、出品者が承認するまでほかの人も購入希望を出せる。Detail のデザインにも「購入希望 n件」がある。
- 一覧に出ない商品を、共有リンク（`/items/:shareId`）で開いたときにどうするか。
- 出品者のアカウントが停止・失効・削除になった商品をどうするか。これは未決事項「失効時に、進行中の取引、公開中の商品、未出金の売上をどう扱うか」（[product/open-questions.md](../product/open-questions.md)）に関わる。

## 決定

| 商品のステータス | 一覧・検索 | 商品ページ（共有リンク） |
| --- | --- | --- |
| 公開中・購入希望あり | 出す | 出す |
| 取引中・取引完了 | 出さない | 売り切れとして出す（購入希望は出せない） |
| 下書き・取り下げ・停止 | 出さない | 見つからない（404。出品者本人も同じ） |

- 出品者のアカウントが使えない（状態が有効でない、または有効期限を過ぎた）商品は、一覧・検索にも商品ページにも出さない。これは読み取るときの絞り込みだけで、商品のステータスは変えない。失効したときの商品・取引・売上の扱いは未決のまま残す。
- 一覧は、最後に公開した日時の新しい順に並べる。続きは、公開日時と ID を組にした位置（cursor）で取る。
- 商品ページに出す出品者の情報は、学部・学科と入学年度だけにする。学籍番号は出さない（DEAL-1）。
- 一覧・商品ページの API もログインを求める（[ADR 0013](0013-frontend-auth-guard.md)）。

## 理由と検討した選択肢

| 選択肢 | 良い点 | 悪い点 |
| --- | --- | --- |
| 一覧に購入希望ありも出す（採用） | 承認されるまでほかの人も購入希望を出せる（DEAL-1）。Detail のデザインと合う | 一覧の商品がすでに誰かに希望されていることがある |
| 一覧は公開中だけ | 一覧が単純 | 最初の購入希望が来た時点で、ほかの人が見つけられなくなる |
| 取引中・取引完了は売り切れ表示（採用） | 共有リンクを後から開いた人に、売れたことが伝わる | 見せる範囲が一覧と商品ページで分かれる |
| 一覧に出ない商品はすべて 404 | 範囲が1つで単純 | 売れた商品の共有リンクが「見つかりません」になる |
| 使えない出品者の商品は読み取り時に除く（採用） | 停止・失効した人の商品に購入希望が来ない。商品を書き換えないので、未決事項が決まった後に変えやすい | 一覧のクエリで users と結合する |
| 出品者の状態を見ない | 単純 | 停止・失効した人の商品が出続ける |

## 影響

- [product/04-browse-search-share.md](../product/04-browse-search-share.md) BROWSE に、出す範囲と並び順を追記した。
- [product/open-questions.md](../product/open-questions.md) の失効時の扱いの項目に、決まるまでは一覧・商品ページに出さないことを注記した（未決のまま）。
- API：`GET /items`（listItems）と `GET /items/shared/{shareId}`（getPublicItem）を [openapi.yaml](../api/openapi.yaml) に追加した。
- Detail の「購入希望 n件」は、取引のテーブル（#24）ができてから購入希望の API で商品ページの応答に足す。
- 一覧は既存のインデックス `items (status, published_at)` を使う。キーワード検索は LIKE の部分一致で、学内の規模では全文検索のインデックスは足さない。
