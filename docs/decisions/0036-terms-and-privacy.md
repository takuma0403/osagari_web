# ADR 0036: 利用規約・プライバシーポリシーと、フェーズ1の試験運用

- 日付: 2026-10-29
- 状態: 採用
- 関連する章ID: OVERVIEW, PAY, CARD, ITEM-1, DEAL-1〜4, AUTH-3, DATA

## 背景

[product/open-questions.md](../product/open-questions.md) の「利用規約とプライバシーポリシー（学生証の保持目的と期間を含む）」が未決で、公開（M7）の前に本文が必要だった（#65）。学生証の保持期間（[ADR 0014](0014-student-card-retention.md)）と禁止出品物（[ITEM-1](../product/03-listing.md)）はすでに決まっていたが、次のことが決まっていなかった。

- 本文の置き場所
- 運営者をどう表記するか、問い合わせの窓口
- 学生証以外の個人情報の保存期間
- フェーズ1（決済がモック）で公開したとき、利用者が実際にお金をどうやり取りするか

## 決定

- 本文の正本を [legal/terms.md](../legal/terms.md) と [legal/privacy.md](../legal/privacy.md) に置く。条文は「第１条（見出し）」の形で書き、章IDは付けない。ほかの docs からは「利用規約 第５条」のように条番号で参照する。`/terms`・`/privacy` の画面はこの本文を載せる（画面は別の issue）。
- **フェーズ1は試験運用とし、実際の売買には使わない。** 代金・手数料・売上・出金はすべて試験用の記録で、規約で実際の売買に使うことを禁じる。本番の決済を始めるときは規約を改定する。
- 大学の公式サービスではないことを明記する。
- 運営者の氏名は掲げず、法令にもとづく求めがあれば遅滞なく答える、と書く。
- 問い合わせの窓口は**未定**（運営者の氏名が相手に伝わらない形にする）。決まるまで利用規約 第12条・プライバシーポリシー 第８条は「（未定）」のままにし、公開できない。
- 学生証以外の個人情報（メールアドレス、学籍番号、商品・取引・売上の記録など）は、アカウントの失効・削除から**3年**で削除するか、個人を特定できない形にする。学生証の画像（3年）とそろえる。
- 保存先の国は、Cloud Storage・Turso のリージョンをデプロイ時に決めたときに書く（[TECH-OPEN](../tech/open-questions.md)）。それまでプライバシーポリシー 第６条は「（未定）」のままにする。
- 利用規約の次の条項は、一般的な規約にならって書いた案で、PR のレビューでユーザーが確認する：アカウントは1人1つ（第３条）、手数料を免れる誘導などの禁止行為（第８条）、措置の理由を説明する義務を負わない（第９条）、損害の上限を取引の代金の額とする（第10条）、変更後に使えば同意とみなす（第11条）、佐賀地方裁判所を専属的合意管轄とする（第13条）。
- アクセスの記録は Cloud Logging の標準の保存期間（30日）に従い、Cloud Run が記録する接続元のIPアドレスも取得する情報に含める。
- 本番の決済を始めるときは、特定商取引法の表記（[PAY-4](../product/06-payment.md)）で運営者の氏名などを示す必要が出る。運営者を掲げない方針は、そのときの規約の改定で見直す。

## 理由と検討した選択肢

| 選択肢 | 良い点 | 悪い点 |
| --- | --- | --- |
| docs/legal/ に置き、画面は別 issue（採用） | 規約は要件ではないので product/ と分けられる。docs の issue だけで閉じる | 画面への反映を別に行う必要がある |
| docs/product/ に章として置く | 既存の章ID検査にそのまま乗る | 要件と規約の本文が混ざる |
| フェーズ1は試験運用で売買しない（採用） | お金の預かり・手数料の規制（PAY-3）に当たらない | 実際の売買には使えない |
| フェーズ1は当事者が受け渡しの場で直接払う | 公開してすぐ使える | 表示上の手数料が実際には取られないなど、規約と実態がずれる |
| 個人情報は失効・削除から3年（採用） | 学生証と同じ期間で説明しやすい。トラブル調査の期間とそろう | 削除・匿名化の仕組みを作る必要がある |
| 期間を決めずに保持 | 実装が要らない | 必要以上に長く持つことになり、説明があいまい |
