# ADR 0047: アカウントの有効期限を在学年限にし、期限を過ぎた学籍番号の新規登録を断る

- 日付: 2026-11-02
- 状態: 採用
- 関連する章ID: AUTH-1, AUTH-3, AUTH-4, AUTHN-2

## 背景

有効期限は「入学年度＋修業年限（医学部医学科は6年、それ以外は4年）」の3月31日だった（AUTH-3）。このため、次の問題があった。

- 留年した学生は、在学中に失効してしまう。未決事項「有効期限の延長の仕組み（留年、医学部医学科などの6年制、大学院進学、編入）」（[product/open-questions.md](../product/open-questions.md)）が残っていた。
- 有効期限を過ぎた学籍番号でも新規登録でき、作った直後に失効していた。

一方、卒業すると大学のメールが使えなくなり、ログイン時の再確認（AUTH-1、30日ごと）でコードを受け取れずにログインできなくなる。卒業生が使い続けることは、有効期限を短くしなくても防げる。

## 決定

- 有効期限の初期値を「入学年度＋在学年限（修業年限の2倍）」の3月31日にする。4年制と表にないコードは8年、医学部医学科は12年。修業年限は AUTH-4 の表に残し、2倍して使う。
- 有効期限（その日の終わりまで使える）を過ぎた学籍番号は、新規登録の最初の画面で断る。推定（`POST /auth/signup/estimate`）とコード送信で 400 `signup_period_ended` を返し、コードのメールを送らない。コード確認とアカウント作成でも同じ判定をする（途中で日付が変わった場合）。
  - 学籍番号だけで決まり、登録の有無に関係しないので、登録済みかどうかを調べる前に判定する（AUTHN-2 の「登録の有無を判別させない」に反しない）。
- 登録済みのユーザーは、状態が有効・停止で、有効期限が旧ルールの初期値のままの行だけ、マイグレーションで新しい値に直す。管理者が変えた有効期限と、失効・削除済みのアカウントは変えない。
- 未決事項のうち留年と6年制は、この期間で吸収できるとして解決にする。大学院進学・編入は未決のまま残す。

## 理由と検討した選択肢

| 選択肢 | 良い点 | 悪い点 |
| --- | --- | --- |
| 修業年限の2倍（在学年限。採用） | 大学の在学年限と同じ考え方で、医学科の留年も吸収できる | 医学科の卒業生のアカウントが長く残る（ただしメールが使えずログインできない） |
| 全員一律8年 | 計算が単純 | 医学科は留年すると在学中に失効しうる |
| 修業年限のまま（据え置き） | 変更がない | 留年で在学中に失効する |
| 期限切れの登録を最初の画面で断る（採用） | コードを送らずに済み、利用者にすぐ伝わる | 推定・コード送信の API にエラーが増える |
| 期限切れの登録をアカウント作成時に断る | 変更が1か所で済む | コード確認・パスワード設定まで進んでから断られる |
