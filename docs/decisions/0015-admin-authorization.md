# ADR 0015: 管理者の判定と管理APIの隠し方

- 日付: 2026-10-20
- 状態: 採用
- 関連する章ID: ADMIN, CARD, STORAGE, API-1, FE

## 背景

管理者機能（ADMIN）の最初の issue（#17 学生証審査API）にあたり、次の点が決まっていなかった。

- 誰が管理者かをどう決めるか。ログインできるのは大学の学生アドレス（AUTHN-2）だけなので、管理者も学生のアカウントになる。
- 管理者でない人が管理API・管理画面に触れたときの応答。API-1 の表では「管理者でない」は 403 `forbidden` としていた。
- 学生証画像の閲覧用の署名付きURLの有効期限（STORAGE は「短時間」とだけ書いていた）。
- 差し戻すときに理由を持つか（AdminCard のデザインに入力欄はない）。

## 決定

- 管理者は、環境変数 `ADMIN_STUDENT_NUMBERS`（学籍番号8桁のカンマ区切り）の**許可リスト**で決める。起動時に形式を検査し、不正なら起動しない。空なら管理者はいない。
- 管理API（`/api/admin/**`）は、**未ログインでも管理者でなくても 404 `not_found`** を返し、存在しないパスと区別できないようにする。判定はミドルウェアで行い、service でも同じ判定をする（二重のチェック）。
- 管理画面（`/admin/**`）への導線は UI に出さない。画面は `GET /api/admin/session`（管理者なら 204）で判定し、404 なら「ページが見つからない」を出す。
- 学生証画像の閲覧用の署名付きURLは **15分**有効。発行するたびに `student_card_views` に閲覧した管理者と日時を記録する。記録は画像を削除した後も残す。
- 管理者も学生アカウントなので、自分の学生証を提出して自分で審査（承認・差し戻し）してよい。禁止しない。
- 差し戻しの理由は持たない。本人は学生証の画面で「差し戻し」の状態だけを見て再提出する。

## 理由と検討した選択肢

| 選択肢 | 良い点 | 悪い点 |
| --- | --- | --- |
| 環境変数の許可リスト（採用） | DB の変更がいらない。管理画面から権限を広げられない | 変えるには再デプロイが要る |
| `users` に role 列 | 再デプロイなしで変えられる | 付与の手段（CLI・SQL）が別に要る。DB を書き換えられると昇格できる |
| `admins` テーブル | 表示名なども持てる | テーブルと付与の手段が増える |
| 権限なしは 404（採用） | 管理APIの存在を知られない | 403 より原因が分かりにくい（管理者は自分で許可リストを確かめる） |
| 権限なしは 403 | 原因が分かりやすい | 管理APIがあることが分かる |
