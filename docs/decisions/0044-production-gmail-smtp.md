# ADR 0044: 本番の Gmail SMTP の設定と送信数の通知

- 日付: 2026-11-01
- 状態: 採用
- 関連する章ID: AUTHN-7, AUTHN-6, COST

## 背景

#41 で、本番の API（Cloud Run）から認証コードのメールを Gmail SMTP で送れるようにする。server の実装（587番ポート・STARTTLS、`SMTP_USERNAME`・`SMTP_PASSWORD`・`SMTP_FROM`）は済んでいる。決めることは、送信元のアドレスとアプリパスワードの置き場所と、AUTHN-6 で「デプロイ時に設定する」としていた送信数の通知の作り方。

## 決定

- 送信元は、アプリ専用の Gmail アカウント `sagadai.osagari@gmail.com` にする。差出人は `佐賀大お下がりフリマ 運営 <sagadai.osagari@gmail.com>`。
- 送信元のアドレスと差出人は `infra/config.sh` に書き、`infra/deploy-server.sh` が環境変数として設定する。アプリパスワードだけを Secret Manager の `smtp-password` に置く。
- 送信数の通知は、API が出す警告（WARN）のログ「コードのメールの送信数が1日の上限に近づいています」に一致するログベースのアラートポリシーで、運用者にメールで知らせる。通知は1時間に1回まで、24時間ログが出なければ自動で閉じる。
- 通知先のメールアドレスはリポジトリに書かず、`infra/setup.sh` を初めて実行するときに環境変数 `ALERT_EMAIL` で渡す。通知チャンネルとアラートポリシーは表示名で探し、あれば作り直さない。

## 理由と検討した選択肢

| 選択肢 | 良い点 | 悪い点 |
| --- | --- | --- |
| アドレスを config.sh に書く（採用） | シークレットが1つで済む（無料枠の有効なバージョン6個に余裕が残る）。設定がリポジトリで見える | 公開するリポジトリにアドレスが載る（差出人として受信者全員に見えるので秘密ではない） |
| アドレスも Secret Manager に置く | リポジトリにアドレスが残らない | シークレットが3つ増え、無料枠ぎりぎりになる |
| ログベースのアラート（採用） | server の変更が要らない。ログが出たらすぐ届く | 2027年9月以降は課金の予定（1件あたり月数十円以下の見込み） |
| ログベースの指標＋指標のアラート | 回数の推移をグラフで見られる | ユーザー定義の指標は課金対象。設定が増える |
| アラートを作らず、ログを手で確認する | 費用がかからない | 上限に近づいても気づくのが遅れる |
