# ADR 0011: 送信数の制限とログインの停止の数え方

- 日付: 2026-10-16
- 状態: 採用
- 関連する章ID: AUTHN-6, AUTHN-2, AUTHN-4, AUTHN-7, API-1

## 背景

#12（送信数の制限と不正対策）を実装するにあたり、AUTHN-6 は「パスワードの入力ミス10回で15分止める」「同じアドレスへのコード送信は1分に1回・1時間に5回まで」「全体の送信数を記録して上限に近づいたら管理者に知らせる」とだけ書いており、次の点が決まっていなかった。

- 回数を何の単位で数えるか（アドレス・端末・IP）。止めたことから登録の有無が分からないようにする方法（AUTHN-2）。
- コード送信の回数を用途（新規登録・パスワード再設定・ログインの再確認）ごとに数えるか、まとめるか。
- パスワード再設定に成功したら入力ミスの回数を戻すか（#11 からの申し送り）。
- 「管理者に知らせる」をどう実現するか。管理者機能（ADMIN）はまだない。
- Cloud Run は最小インスタンス数0で、複数のインスタンスが動くこともあるため、メモリ上の回数は失われる・共有されない。

## 決定

- **単位はアドレスだけ**（ユーザーが選択）。IP 単位は送信元IPの取り方（Firebase Hosting 経由の `X-Forwarded-For`）の検討を含めて別の issue にする。端末識別子は利用者側で消せるので使わない。
- 回数は DB に持つ（インスタンスをまたいで共有し、再起動で失われないようにする）。
- **パスワードの入力ミス**：新しいテーブル `login_failures`（メールアドレスを主キー）に回数と止める期限を持つ。ユーザーではなく正規化したアドレスで持ち、未登録・削除済みのアドレスも同じように数えて止める。回数は ADR 0007 のコードと同じく**照合の前に**条件付きUPDATE（`locked_until IS NULL AND failed_attempts < 10` のときだけ +1）で数え、同時に大量に送られても照合は10回までにする。10回目の照合に失敗したら15分止める。止めている間は照合せずに `429 too_many_requests`（共通コード）を返す。期限が過ぎたら回数を0から数え直す。パスワードが一致したら回数を0に戻す。
- **パスワード再設定の後**（ユーザーが選択）：回数だけ0に戻し、止めている間は期限まで止めたままにする。
- **コード送信**：用途を**まとめて**アドレスごとに数える（ユーザーが選択）。新しいテーブルは作らず `verification_codes` の行（登録済み・未登録とも1回の送信で1行を保存している）を数える。判定と保存を1つの条件付き INSERT で行い、同時に送られても上限を超えないようにする。保存できたときだけ古いコードを無効にするので、断ったときはそれまでのコードが使える。応答は `429 too_many_requests` で、1分以内か1時間5回かでメッセージを変える。
- **全体の送信数**（ユーザーが選択）：`verification_codes` の直近24時間の行数を数え、400通以上なら送るたびに WARN のログを出す（アドレスは出さない）。送信は止めない。ログからの通知（Cloud Logging のアラート）はデプロイ（M7）で設定する。
- `Retry-After` ヘッダーは付けず、メッセージで待ち時間の目安を伝える。

## 理由と検討した選択肢

| 選択肢 | 良い点 | 悪い点 |
| --- | --- | --- |
| **アドレス単位のみ（採用）** | 仕様の数字どおり。送信元IPの信頼性の問題がない | 多数のアドレスを順に狙う攻撃は止められない（コード送信は送信数の警告で気づく） |
| IP 単位も入れる | 多数のアドレスへの攻撃を抑えられる | Firebase Hosting 経由での送信元IPの取り方と偽装対策の検討が要る。大学のNATで同じIPの利用者が巻き込まれうる |
| **アドレスで持つ（採用）** | 未登録でも同じように止まり、登録の有無が分からない | 存在しないアドレスの行もできる |
| ユーザーで持つ | 行が少ない | 未登録のアドレスだけ止まらず、429 の有無から登録が分かる |
| **照合の前に数える（採用）** | 同時大量入力でも上限を守れる | 成功した回も一度数える（成功で0に戻すので影響しない） |
| **用途をまとめて数える（採用）** | アドレスへのメール総数を抑えられ、用途を変えて回避されない | 新規登録と再設定を同じ時間内に使うと互いに影響する（通常は起きない） |
| **再設定で回数だけ戻す（採用）** | 本人が再設定したら次のミスを0から数えられる。止めている間に再設定しても、総当たりの途中で止めた効果は期限まで残る | 本人もロックの期限までは待つ |
| 再設定でロックも解除する | 本人がすぐ使える | 総当たりを疑って止めた直後に解除され、止めた効果が短くなる |
| **警告ログのみ（採用）** | 送信を止めないので利用者に影響しない。管理者機能なしで作れる | 上限を超えた分は Gmail 側で失敗する |
| 上限で送信を止める | Gmail の制限に当たる前に止まる | 正当な利用者も送れなくなる |
