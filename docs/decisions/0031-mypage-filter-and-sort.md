# ADR 0031: マイページの履歴の状態の絞り込みと並べ替え

- 日付: 2026-10-27
- 状態: 採用
- 関連する章ID: AUTH-3, ITEM, DS-4

## 背景

マイページ（[MyPage](../design/screens/MyPage.dc.html)）の「出品した商品」「購入した商品」は、最後に動いた順の一覧だけだった（[ADR 0030](0030-mypage-history.md)）。出品が増えると、購入希望の届いた商品や下書きを探しにくい。デザインには絞り込みも並べ替えもないが、ユーザーが先に実装し、デザインは後で直すと決めた。

## 決定

- タブごとに**状態の絞り込み**を置く。チップは「すべて」と、いま一覧にある状態だけを出す（ない状態のチップは出さない）。
  - 出品した商品：公開中／購入希望あり／取引中／売却済み／下書き／取り下げ／停止中
  - 購入した商品：取引中／完了
- **並べ替え**はセレクトボックスで「新しい順」（既定）と「古い順」を選ぶ。基準はどちらのタブも最後に動いた日時（`updatedAt`）。出品は編集と状態の変化（購入希望・承認・完了など）で、購入は取引の状態の変化で変わる。購入した商品は取引中と完了を混ぜて日時順に並べる。
- 絞り込みも並べ替えも、読み込んだ一覧をブラウザで処理する（API は変えない）。
- 選んだ状態と並び順は URL のクエリ（`status`、`order=asc`）に持つ。タブを替えたら状態の絞り込みは外し、並び順は残す。一覧にない状態がクエリにあれば絞り込まない。
- 名前での検索、金額での並べ替えは作らない（1人の出品・購入は数十件ほどで、一覧で探せるため）。

## 理由と検討した選択肢

| 選択肢 | 良い点 | 悪い点 |
| --- | --- | --- |
| 一覧にある状態だけチップに出す（採用） | チップが少なく、押して0件になることがない | 一覧が変わるとチップの数も変わる |
| すべての状態のチップを出す | 位置が変わらない | 出品で8つ並び、多くが0件 |
| ブラウザで絞り込み・並べ替え（採用） | API の変更が要らない。全件を読み込み済み | 件数が大きく増えたら API に移す必要がある |
| API にパラメーターを足す | 件数が増えても軽い | server の issue が要る。いまの件数では不要 |
| 購入は取引中を上に固定 | 進んでいる取引が目立つ | 「古い順」の意味がわかりにくい |
