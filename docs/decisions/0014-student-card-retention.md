# ADR 0014: 学生証画像の保持期間と再提出時の扱い

- 日付: 2026-10-19
- 状態: 採用
- 関連する章ID: CARD, STORAGE, DATA, JOBS-1

## 背景

[product/open-questions.md](../product/open-questions.md) の「利用規約とプライバシーポリシー（学生証の保持目的と期間を含む）」のうち、保持期間の数字は学生証登録API（#15）の着手時に決めることになっていた。規約の本文は #65 でこの期間を使って書く。

あわせて、審査中の撮り直しや差し戻し後の再提出で使われなくなった画像をどうするかが決まっていなかった。

## 決定

- 学生証画像は、**アカウントの失効・削除から3年間**保持し、その後に日次ジョブで削除する（`student_cards.delete_after` = 失効・削除日 + 3年）。
- 再提出で使われなくなった画像も**すべて残し**、同じく失効・削除から3年で削除する。前の行には置き換えた日時（`superseded_at`）を入れ、審査の対象は置き換えられていない最新の1件だけにする。

## 理由と検討した選択肢

| 選択肢 | 良い点 | 悪い点 |
| --- | --- | --- |
| 期間 3年（採用） | すでに CARD・画面の文言に書かれている。トラブル時に当事者を特定する余地が十分ある | 1年より長く個人情報を持つ |
| 期間 1年・5年 | 短いほど持つ情報が減る／長いほど調査できる期間が延びる | 仕様・画面の文言の変更が要る |
| 再提出前の画像もすべて残す（採用） | 当事者を特定する材料が最も多い。差し替えによる証拠隠しを防げる | 保存する個人情報と容量が増える |
| 審査前に撮り直したものだけ消す | 不要な画像を減らせる | 審査前の画像も不正の手がかりになりうる |
| 最新の1枚以外すぐ消す | 保存する情報が最小 | 差し戻した画像の記録が残らない |

- [product/02-student-card.md](../product/02-student-card.md) CARD、[product/09-data-model.md](../product/09-data-model.md) DATA、[tech/storage.md](../tech/storage.md) STORAGE、[product/open-questions.md](../product/open-questions.md) に反映した。
- `student_cards` に `superseded_at` と `delete_after` を持たせる（`migrations/000008`）。`delete_after` を入れる処理と画像の削除は、失効・削除と日次ジョブ（JOBS-1）の issue で実装する。
- 利用規約・プライバシーポリシー（#65）には、再提出前の画像も保持することを書く。
